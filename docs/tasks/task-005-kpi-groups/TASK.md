## 1. User story

> **Я как пользователь дашборда хочу группировать карточки KPI по смыслу («Объём», «Темп», «Пульс», «Регулярность»), чтобы показатели одного типа собирались вместе и глаз быстрее находил нужный.**

Источник: `docs/ROADMAP.md`, Блок 1, пункт 5.

---

## 2. Контекст: что есть сейчас

Сейчас все 10 KPI-карточек лежат в одной плоской сетке, поэтому метрики разного смысла (объём, пульс, регулярность) визуально не разделены и глаз вынужден сканировать их все подряд.

**Разметка** — `running-dashboard 3.html`, строки 675–737:

```html
<section class="kpi-grid" id="kpi-grid">
  <div class="kpi-card" data-kpi="7d">        <!-- За последние 7 дней -->
  <div class="kpi-card" data-kpi="month">     <!-- За текущий месяц -->
  <div class="kpi-card" data-kpi="count">     <!-- Число тренировок -->
  <div class="kpi-card" data-kpi="avg_km">    <!-- Средняя дистанция -->
  <div class="kpi-card" data-kpi="avg_pace">  <!-- Средний темп -->
  <div class="kpi-card" data-kpi="w_pulse">   <!-- Ср. пульс (на км) -->
  <div class="kpi-card" data-kpi="max_pulse"> <!-- Средний макс. пульс -->
  <div class="kpi-card" data-kpi="longest">   <!-- Самая длинная -->
  <div class="kpi-card" data-kpi="streak">    <!-- Серия дней подряд -->
  <div class="kpi-card" data-kpi="trend">     <!-- Тренд (4 нед. к пред. 4) -->
</section>
```

**Ключевые точки, которые нельзя сломать:**

| Что | Где | Почему важно |
|---|---|---|
| Идентификаторы элементов `kpi-km7`, `kpi-kmm`, `kpi-cnt-period`, `kpi-avg-km`, `kpi-avg-pace`, `kpi-wpulse`, `kpi-maxpulse`, `kpi-longest`, `kpi-streak`, `kpi-trend` | `renderKPIs()`, строки 1802–1894 | Функция пишет значения по `id` — если id или порядок в DOM изменятся, цифры перестанут выводиться |
| Атрибут `data-kpi` | 10 карточек + обработчик клика, строки 3951–3972 | Обработчик навешен на `#kpi-grid` делегированно и определяет тип метрики через `card.dataset.kpi` |
| Поведение клика | строки 3951–3972 | Клик открывает панель детализации (`showDrillListPanel`) — поведение должно сохраниться |
| Стили `.kpi-grid`, `.kpi-card`, `.badge`, `.progress-mini` | строки 253–299 | Сетка `repeat(5, 1fr)` рассчитана на 10 карточек в 2 ряда; при появлении групп её надо переработать |
| `state.settings` | строки 1547–1556 | Уже сохраняется в `localStorage` через `STORAGE_KEYS.settings` (`run_pro_settings_v2`) — настройку групп логично хранить там же |
| `loadStateFromStorage()` / `saveAllState()` | строки 1580–1604 | `Object.assign({}, state.settings, s)` — новый ключ в `settings` подхватится автоматически, но применить его к DOM нужно **до** `renderAll()` |
| Тема оформления | `:root[data-theme="dark"]` / `[data-theme="light"]`, строки 9–57; `applyTheme()`, строка 3523 | Новые элементы обязаны работать в обеих темах |
| Адаптивность | `body { min-width: 1180px }`, строка 64 | Группы не должны ухудшать текущую горизонтальную компоновку |

## 3. Цель

Разложить 10 KPI-карточек по 4 смысловым группам с видимыми заголовками, сделать группы сворачиваемыми и позволить пользователю перенастроить раскладку под себя.

---

## 4. Пользовательский сценарий

**Основной путь:**

1. Пользователь открывает дашборд → сразу видит четыре блока с подписями «📦 Объём», «⚡ Темп», «❤️ Пульс», «🔥 Регулярность» вместо плоской сетки из 10 карточек.
2. Понимает, что блоки означают разные срезы данных (объём / интенсивность / реакция организма / дисциплина) и находит нужную цифру, не сканируя все 10.
3. Кликает по заголовку группы → группа сворачивается в одну строку-заголовок, освобождая место; повторный клик разворачивает обратно.
4. Кликает по карточке внутри группы → открывается та же панель детализации, что и раньше (поведение не изменилось).

**Дополнительный путь (P1):**

5. Нажимает «⚙ Настроить KPI» → открывается модальное окно со списком групп и карточек.
6. Перетаскивает карточку «Средняя дистанция» из группы «Объём» в «Темп» — новая раскладка применяется сразу и сохраняется.
7. Переименовывает группу, скрывает группу целиком или отдельную карточку.
8. Нажимает «Сбросить» → возвращается штатная раскладка из `payload.json`.

---

## 5. Требования

### P0 — обязательно

1. **Четыре группы по умолчанию.** Стартовая раскладка берётся из `payload.json` → `defaultKpiGroups` и покрывает все 10 карточек ровно один раз.

   | Группа | Карточки (`data-kpi`) |
   |---|---|
   | 📦 Объём | `7d`, `month`, `count`, `longest` |
   | ⚡ Темп | `avg_km`, `avg_pace` |
   | ❤️ Пульс | `w_pulse`, `max_pulse` |
   | 🔥 Регулярность | `streak`, `trend` |

2. **Заголовок группы.** Элемент `<header class="kpi-group-head">` с иконкой, названием и количеством карточек в группе.

3. **Сворачивание.** Клик по заголовку (кнопка `<button aria-expanded="true|false">`) сворачивает/разворачивает тело группы. В свёрнутом виде остаётся только заголовок с иконкой, названием и числом метрик.

4. **Сохранение состояния.** Развёрнутость групп и пользовательская раскладка сохраняются в `state.settings.kpiGroups` → `localStorage['run_pro_settings_v2']`. После перезагрузки страницы раскладка и состояние свёрнутости восстанавливаются.

5. **Отсутствие регрессий.** `renderKPIs()` продолжает находить все 10 карточек по `id`; клик по карточке продолжает открывать детализацию; экспорт/импорт JSON продолжает работать (ключ `kpiGroups` не должен попадать в файл тренировок).

6. **Обе темы.** Цвета заголовков, разделителей, шевронов и hover-состояний берутся из существующих CSS-переменных (`--text`, `--muted`, `--border`, `--card`, `--accent`, `--blue`).

7. **Адаптивная сетка внутри группы.** Карточки внутри группы раскладываются через `repeat(auto-fit, minmax(190px, 1fr))`, чтобы группа из 2 и группа из 4 карточек выглядели одинаково аккуратно.

8. **Порядок применения при загрузке.** Пользовательская раскладка применяется к DOM **до** вызова `renderAll()` — иначе `renderKPIs()` запишет значения в карточки, оставшиеся вне групп.

### P1 — желательно

9. **Модальное окно «⚙ Настроить KPI»**: переименование группы, перемещение карточек между группами (drag & drop на HTML5 Drag API, без внешних библиотек), скрытие группы, скрытие отдельной карточки (скрытая карточка переносится в блок «Скрытые»).
10. **Кнопка «Сбросить к умолчанию»** в модальном окне настроек.
11. **Счётчик метрик** в заголовке группы: «4 метрики» / «1 метрика» / «4 метрики» (русские окончания).
12. **Кнопки «Свернуть всё» / «Развернуть всё»** рядом с сеткой KPI.

### P2 — можно оставить на потом

13. Компактный режим (уменьшенные карточки без прогресс-баров).
14. Экспорт/импорт раскладки групп отдельным файлом.

## 7. Структура данных

Формат хранения — в `payload.json`. Кратко:

```js
state.settings.kpiGroups = {
  version: 1,
  groups: [
    { id: 'volume', icon: '📦', title: 'Объём', collapsed: false, hidden: false, cards: ['7d', 'month', 'count', 'longest'] },
    { id: 'pace', icon: '⚡', title: 'Темп', collapsed: false, hidden: false, cards: ['avg_km', 'avg_pace'] },
    { id: 'pulse', icon: '❤️', title: 'Пульс', collapsed: false, hidden: false, cards: ['w_pulse', 'max_pulse'] },
    { id: 'consistency', icon: '🔥', title: 'Регулярность', collapsed: false, hidden: false, cards: ['streak', 'trend'] }
  ],
  hiddenCards: []
}
```

Правила валидации при загрузке:
- если ключа в `localStorage` нет или JSON битый — используется `defaultKpiGroups`;
- если в сохранённой раскладке встречается неизвестный `data-kpi` — он игнорируется;
- если какая-то из 10 карточек отсутствует в раскладке — она автоматически возвращается в группу по умолчанию;
- при изменении состава карточек в коде новые карточки подхватываются автоматически (проверка по списку `data-kpi` из DOM).

## 8. Критерии приёмки

- [ ] На странице видны 4 группы с заголовками и иконками; все 10 карточек распределены, ни одна не потеряна и не продублирована.
- [ ] Каждая карточка показывает то же значение, что и до изменения (проверяется на демо-данных «⚡ Демо-данные (60)»).
- [ ] Клик по любой карточке открывает панель детализации с тем же заголовком и списком, что и раньше.
- [ ] Клик по заголовку группы сворачивает её; состояние `aria-expanded` меняется; содержимое группы скрывается, но заголовок и число метрик остаются.
- [ ] После перезагрузки страницы развёрнутость групп сохраняется.
- [ ] Перемещение карточки между группами в модальном окне применяется сразу и сохраняется после перезагрузки.
- [ ] «Сбросить к умолчанию» возвращает исходную раскладку и очищает настройку.
- [ ] Схема корректна в тёмной и светлой темах; в заголовках групп читаемый контраст.
- [ ] Горизонтальная компоновка страницы не сломалась: при ширине 1280–1920 px группы выстроены в 2 колонки, карточки внутри — равномерно.
- [ ] Экспорт JSON не содержит `kpiGroups`; импорт JSON не ломает состояние.
- [ ] В `console` нет ошибок; добавление/удаление тренировки не ломает раскладку.

## 9. Риски и как их снимать

| Риск | Снятие |
|---|---|
| Сломать `renderKPIs()`, который пишет по `id` | Не переименовывать `id` карточек, не менять их порядок внутри разметки — только оборачивать в группы |
| Сломать делегированный клик по `#kpi-grid` | Сохранить делегирование на общем контейнере `#kpi-groups`; проверить, что `e.target.closest('.kpi-card')` по-прежнему находит карточку через вложенные элементы |
| Потерять пользовательскую раскладку при обновлении страницы | Валидация сохранённых данных + автодобавление новых карточек + кнопка сброса |
| Усложнить и без того плотную шапку страницы | Заголовки групп компактные, без дополнительных декораций; кнопка настроек — одна, рядом с заголовком секции |
| Разные экраны по ширине | Внутри группы — `auto-fit minmax()`, сетка секции — `repeat(auto-fit, minmax(420px, 1fr))` |
