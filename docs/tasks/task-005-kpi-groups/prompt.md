## Промпт

Ты — фронтенд-разработчик. Работаешь с **одним самодостаточным HTML-файлом** `running-dashboard 3.html` (дашборд беговых тренировок: inline CSS + inline JS + Chart.js с CDN). Внешние библиотеки, кроме уже подключённого Chart.js, использовать **нельзя**. Никаких сборщиков, фреймворков и модулей — всё остаётся в одном файле.

### Задача

Сейчас 10 KPI-карточек лежат в одной плоской сетке `#kpi-grid` (`.kpi-grid { grid-template-columns: repeat(5, 1fr); }`) и визуально не разделены по смыслу. Нужно разложить их по 4 смысловым группам с заголовками и дать пользователю возможность настроить раскладку.

**Что обязательно сделать (P0):**

1. **Четыре группы по умолчанию.** Стартовая раскладка — из `docs/tasks/task-005-kpi-groups/payload.json` → `defaultKpiGroups`:

   | Группа | `data-kpi` карточек |
   |---|---|
   | 📦 Объём | `7d`, `month`, `count`, `longest` |
   | ⚡ Темп | `avg_km`, `avg_pace` |
   | ❤️ Пульс | `w_pulse`, `max_pulse` |
   | 🔥 Регулярность | `streak`, `trend` |

2. **Заголовок группы** `<header class="kpi-group-head">`: иконка, название, счётчик метрик («4 метрики» с правильным русским окончанием), кнопка сворачивания-разворачивания.

3. **Сворачивание.** Клик по кнопке в заголовке сворачивает тело группы; в свёрнутом виде остаётся только заголовок. Используй `<button aria-expanded="true|false">` и CSS-переход, уважай `prefers-reduced-motion` (в файле уже есть такой блок — не сломай его).

4. **Сохранение.** Состояние (раскладка + свёрнутость + скрытые группы/карточки) храни в `state.settings.kpiGroups` и сохраняй через существующий `saveAllState()` → `localStorage['run_pro_settings_v2']`. При загрузке — из `loadStateFromStorage()`.

5. **Порядок при загрузке.** Пользовательская раскладка применяется к DOM **до** `renderAll()` (иначе `renderKPIs()` не найдёт карточки по `id`).

**Что желательно (P1):**

6. **Модальное окно «⚙ Настроить KPI»**: переименование группы, перемещение карточек между группами drag & drop (HTML5 Drag API, без библиотек), скрытие группы, скрытие отдельной карточки (скрытые карточки — в блок «Скрытые»), кнопка «Сбросить к умолчанию».
7. Кнопки «Свернуть всё» / «Развернуть всё» рядом с заголовком секции.

### Жёсткие ограничения (сломать нельзя)

- **Не менять `id` карточек**: `kpi-km7`, `kpi-kmm`, `kpi-cnt-period`, `kpi-avg-km`, `kpi-avg-pace`, `kpi-wpulse`, `kpi-maxpulse`, `kpi-longest`, `kpi-streak`, `kpi-trend`. `renderKPIs()` пишет значения по этим `id`.
- **Не менять значения `data-kpi`**: `7d`, `month`, `count`, `avg_km`, `avg_pace`, `w_pulse`, `max_pulse`, `longest`, `streak`, `trend`. Обработчик клика (строки ~3951) определяет тип метрики через `card.dataset.kpi`.
- **Сохранить делегирование клика.** Сейчас обработчик навешен на `$('kpi-grid')` и ищет `e.target.closest('.kpi-card')`. Если контейнер переименуется — поведение клика по карточке (открытие `showDrillListPanel`) должно работать точно так же.
- **Не ломать** `renderKPIs()`, `renderAll()`, экспорт/импорт JSON, CSV-импорт, настройки пульсовых зон, ИИ-ввод голосом.
- **Ключ `kpiGroups` не должен попадать** в экспорт JSON с тренировками.
- **Темы.** Используй существующие CSS-переменные (`--bg`, `--card`, `--border`, `--text`, `--muted`, `--accent`, `--blue`, `--danger`). Новые элементы обязаны читаться в тёмной и светлой темах.
- **Стиль кода.** Именование в стиле файла (`kpi-group`, `kpi-group-head`, `kpi-group-body`), комментарии на русском в стиле существующих (`/* ==== ... ==== */`), никаких новых глобальных переменных без префикса.

### Требования к вёрстке и стилям

- Сетка секции групп: `repeat(auto-fit, minmax(420px, 1fr))`, `gap: 16px` — на широких экранах 2 колонки.
- Карточки внутри группы: `repeat(auto-fit, minmax(190px, 1fr))` — группа из 2 и из 4 карточек выглядят одинаково аккуратно.
- Каждая группа — отдельная карточка-панель со своим фоном, рамкой и заголовком-разделителем.
- Сейчас `.kpi-grid` рассчитан на 5 колонок — переработай под новую структуру, но сохрани визуал карточек (`.kpi-card`, `.badge`, `.progress-mini`).

### Валидация сохранённых данных

- Нет ключа / битый JSON → используется `defaultKpiGroups`.
- Неизвестный `data-kpi` в раскладке → игнорируется.
- Карточка, отсутствующая в раскладке → возвращается в группу по умолчанию.
- Новая карточка, добавленная в разметку → автоматически попадает в группу по умолчанию.
- Карточка не может числиться в двух группах — остаётся первое вхождение.
- Пустая группа отображается как «0 метрик» и не ломает сетку.
