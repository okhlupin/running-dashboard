## 1. User story

> **Я как бегун хочу прогноз даты достижения цели по текущему темпу прогресса, чтобы понимать, реально ли успеть к объёму месяца или квартала.**

Источник: `docs/ROADMAP.md`, Блок 4, пункт 17.

---

## 2. Контекст: что есть сейчас

Приложение умеет показывать **факт против цели** (сколько набегано из скольких нужно), но не отвечает на вопрос «**когда** я добегу цель». Пользователь видит в KPI-карточке «За текущий месяц» 88.0 / 75 км (117 %) и в шапке с бегуном — ту же строку, но дальше приходится считать в уме: по текущему темпу успею ли я к концу квартала.

**Уже готово и можно переиспользовать:**

| Что | Где | Как используем |
|---|---|---|
| `state.goals = { defaultGoal, preset, byMonth }` | строки 1541–1546 | Источник цели на месяц |
| `calcGoalForMonth(ym, goalsConfig)` | строки 1435–1440 | Берём цель месяца с учётом `byMonth` |
| `state.plans` + `calcPlanForDate()` | строки 1405–1432 | Не нужен, но полезен для «нужного» темпа по плану |
| `state.settings` | строки 1547–1556 | Храним здесь цели квартала/года и окно расчёта темпа |
| `getRunsByTypeOnly()` | строки 1740–1742 | Тренировки с учётом фильтра по типам |
| `getPeriodBounds()` | строки 1693–1727 | Границы периодов `cur_month` / `quarter` / `year` |
| `toISO`, `parseISO`, `addDaysISO`, `listDaysBetween`, `pad2` | строки 1259–1294 | Работа с датами |
| `fmtNum`, `fmtDateShort`, `fmtDateFull` | строки 1296–1312 | Форматирование |
| `getBadgeClassByPct(pct)` | строки 1527–1531 | Цвет бейджа по проценту (зелёный ≥ 100, жёлтый 80–99, красный < 80) |
| `updateRunnerPositionAndStatus()` | строки 1759–1779 | Строка статуса в шапке — место для короткого прогноза |

**Чего нет:** ни одной функции прогнозирования, ни целей на квартал/год, ни отображения ожидаемой даты.

---

## 3. Цель

Показывать ожидаемую дату достижения цели, отставание/опережение и необходимый темп — по месяцу, кварталу и году.

---

## 4. Пользовательский сценарий

**Основной путь:**

1. Пользователь открывает дашборд → в левой колонке под блоком «🎯 Недельный план и Цель месяца» появляется карточка «📅 Прогноз достижения цели».
2. Видит: цель месяца 75 км, факт 60 км, текущий темп 25 км/нед, **прогноз: 26 окт** — «🎉 Успеваем, за 5 дней до срока».
3. Понимает, что цель успеет, и переключает период на «Квартал» → «⏳ Успеваем, цель будет 11 дек (год)».
4. Переключает на «Год» → «⚠️ Отстаём: цель будет достигнута 12 фев, на 43 дня позже срока», строка «нужно 24.0 км/нед, сейчас 20.0 км/нед» показывает дефицит темпа.

**Дополнительный путь:**

5. Вводит свою цель квартала (300 км) и года (1000 км) → прогноз пересчитывается сразу, значения сохраняются.
6. Меняет окно расчёта темпа (7 / 28 / 56 / 90 дней) → прогноз пересчитывается по новому окну.
7. В шапке с бегуном строка статуса дополняется прогнозом: `Цель месяца (2026-10): 88.0 / 75 км (117%) · Цель уже достигнута`.

**Крайние случаи (обязательно обработать):**

| Ситуация | Что показываем |
|---|---|
| Цель уже набегана | 🎉 «Цель уже достигнута», дата = сегодня |
| Нет ни одной тренировки в окне | «Нет данных о темпе» — прогноз не считаем, но показываем нужный темп |
| Нужно ускориться | ⚠️ «Отстаём», дефицит темпа в км/нед |
| Период уже закончился (просмотр прошлого месяца) | «Период завершён», итог факт/цель без прогноза |
| Часовой пояс / граница месяца | Расчёт ведётся в календарных днях, без UTC |

## 5. Требования

### P0 — обязательно

1. **Чистая функция расчёта.** В раздел «ЧИСТЫЕ ФУНКЦИИ РАСЧЁТОВ» (после `calcGoalForMonth`, ~строка 1440) добавить:

   ```js
   /**
    * Прогноз достижения цели по текущему темпу.
    * @param {number} goalKm        — цель периода, км
    * @param {number} actualKm      — уже набегано за период, км
    * @param {number} paceKmPerWeek — текущий темп, км/нед
    * @param {string} todayISO      — сегодня (YYYY-MM-DD)
    * @param {string} targetISO     — последний день периода (YYYY-MM-DD)
    * @returns {{status, goalKm, actualKm, remainingKm, paceKmPerWeek,
    *            requiredKmPerWeek, paceDeltaKmPerWeek, daysLeft, daysNeeded,
    *            forecastDateISO, daysEarly, daysLate}}
    */
   function calcGoalForecast(goalKm, actualKm, paceKmPerWeek, todayISO, targetISO) { ... }
   ```

   Функция **не читает DOM и не трогает состояние** — только считает. Это обязательное требование: её можно вызвать вручную из консоли и проверить на тест-векторах из `payload.json`.

2. **Правила расчёта** (зафиксированы, чтобы результат был предсказуемым):

   ```
   remainingKm   = max(0, goalKm - actualKm)
   daysLeft     = количество календарных дней от today до target включительно
   requiredKmPerWeek = remainingKm / (daysLeft / 7)
   paceDeltaKmPerWeek = paceKmPerWeek - requiredKmPerWeek
   daysNeeded   = ceil(remainingKm / paceKmPerWeek * 7)      // при pace > 0
   forecastDateISO = addDaysISO(today, daysNeeded - 1)        // сегодня = 1-й день
   status:
     'achieved'  — actualKm >= goalKm
     'no-data'   — paceKmPerWeek <= 0 и remainingKm > 0
     'on-track'  — forecastDateISO <= targetISO
     'behind'    — forecastDateISO > targetISO
   daysEarly = max(0, daysLeft - daysNeeded)   // на сколько дней раньше срока
   daysLate  = max(0, daysNeeded - daysLeft)   // на сколько дней позже срока
   ```

3. **Темп прогноза.** `paceKmPerWeek = сумма км за окно / (окно / 7)`, окно по умолчанию 28 дней, варианты 7 / 28 / 56 / 90 (настройка `state.settings.forecastWindowDays`). Окно считается **календарно** (с сегодняшнего дня назад), тренеры учитываются через `getRunsByTypeOnly()` — то есть фильтр типов тренировок влияет на прогноз так же, как на остальные метрики.

4. **Факт за период.** Сумма км по тренировкам, попадающим в границы выбранного периода (месяц / квартал / год) **и** в фильтр типов.

5. **Карточка «📅 Прогноз достижения цели»** в левой колонке, сразу после карточки «🎯 Недельный план и Цель месяца». Состав:
   - переключатель периода: `Месяц` / `Квартал` / `Год`;
   - крупная строка прогноза: дата + статус (бейдж);
   - строка «Факт / Осталось»;
   - строка «Темп сейчас / Нужно темп» + подсветка дефицита;
   - прогресс-бар выполнения цели (использовать `.progress-mini`);
   - подпись с окном расчёта темпа;
   - поля целей квартала и года.

6. **Цели квартала и года.** Новые поля в `state.settings.forecastGoals = { quarter: 300, year: 1000 }` с полями ввода в карточке и кнопкой сохранения. Хранение — существующий `saveAllState()` → `localStorage['run_pro_settings_v2']`. Значения по умолчанию: квартал 300 км, год 1000 км (≈ 83 км/мес).

7. **Цель месяца берётся из существующего механизма** — `calcGoalForMonth(ym, state.goals)`. Новую логику хранения целей не заводить.

8. **Строка в шапке с бегуном.** Дополнить `runner-status-text` (строка 1767) прогнозом: `Цель месяца (2026-10): 88.0 / 75 км (117%) · Прогноз: цель уже достигнута` / `· Прогноз: 26 окт, на 5 дней позже`. Строка должна остаться в одну строку на широком экране и не ломать анимацию бегуна.

9. **Обе темы.** Текст, бейджи и полосы используют существующие CSS-переменные (`--accent`, `--danger`, `--amber`, `--blue`, `--muted`, `--border`).

10. **Пустое состояние.** Если тренировок нет вообще — карточка показывает «Нет данных о темпе», а не нули и не `NaN`.

### P1 — желательно

11. **KPI-карточка «Прогноз цели»** в секции KPI (11-я карточка) с датой прогноза и статусом. *Если задача [task-005](task-005-kpi-groups/TASK.md) уже выполнена — карточка добавляется в группу «📦 Объём»; если нет — отдельной строкой в общей сетке.*
12. **Сравнение с планом.** Показывать не только «нужно X км/нед», но и требуемый темп по недельному плану (`state.plans.defaultWeek.weeklyKm`) — два числа рядом: «нужно по факту» и «нужно по плану».
13. **Три уровня уверенности** прогноза: по темпу за 28 дней / по среднему за 56 / по тренду последних 4 недель к предыдущим 4 (переиспользовать `calcFourWeekTrend`).
14. **История прогнозов.** Сохранять в `state.settings.forecastHistory` связку «дата прогноза → прогнозная дата» и показывать график «как менялся прогноз» (стрелки «было → стало»).

### P2 — можно оставить на потом

15. Прогноз по произвольному периоду (`state.filters.period === 'custom'`).
16. Экспорт прогноза в PDF-отчёт (связано с историей № 20).
17. Уведомление «цель будет достигнута через N дней» при открытии дашборда.

## 6. Формулировки интерфейса

| Статус | Заголовок | Подпись |
|---|---|---|
| `achieved` | 🎉 Цель уже достигнута | `Факт 78.0 км при цели 75.0 км` |
| `on-track` | 🎉 Успеваем | `Прогноз: 26 окт — на 5 дней раньше срока (31 окт)` |
| `behind` | ⚠️ Отстаём | `Прогноз: 12 фев — на 43 дня позже срока (31 дек)` |
| `no-data` | ⛔ Нет данных о темпе | `За 28 дней нет тренировок — нужен темп 40.3 км/нед` |

Русские окончания («43 дня», «5 дней», «1 день») — через общий хелпер, аналогичный `plural()` из макета task-005.

## 9. Критерии приёмки

- [ ] Карточка «📅 Прогноз достижения цели» появляется в левой колонке под блоком целей и не сдвигает/не ломает существующие блоки.
- [ ] `calcGoalForecast()` возвращает значения из тест-векторов §8 (проверяется вызовом из консоли).
- [ ] Функция не обращается к DOM и не меняет `state`.
- [ ] Переключение периода «Месяц / Квартал / Год» пересчитывает факт, цель и прогноз.
- [ ] Цель месяца берётся из `state.goals` — изменение цели в блоке «Цель на месяц» сразу меняет прогноз.
- [ ] Цели квартала и года сохраняются и переживают перезагрузку страницы.
- [ ] Окно расчёта темпа переключается (7/28/56/90) и меняет прогноз.
- [ ] Фильтр типов тренировок влияет на прогноз (как и на остальные метрики).
- [ ] Все 4 статуса отображаются корректно, включая `no-data` без `NaN` и без нулей вместо прочерков.
- [ ] Строка в шапке с бегуном дополнена прогнозом и не ломает анимацию/вёрстку.
- [ ] Русские окончания в подписях корректны («43 дня», «5 дней»).
- [ ] Тёмная и светлая темы: контраст текста и бейджей в норме.
- [ ] `prefers-reduced-motion` не нарушен.
- [ ] Экспорт/импорт JSON, CSV-импорт и ИИ-ввод продолжают работать; новые ключи в экспорт тренировок не попадают.
- [ ] В `console` нет ошибок; добавление/удаление тренировки пересчитывает прогноз.

## 10. Риски и как их снимать

| Риск | Снятие |
|---|---|
| Прогноз вводит в заблуждение (по одному окну нельзя судить) | Показать окно и метод расчёта в подписи; дефолт 28 дней; в P1 — три уровня уверенности |
| Разные границы месяца при вычислении «дней осталось» | Считать в календарных днях через `listDaysBetween`, не в часах |
| Дробные значения «прогноз 4.2 дня» | Дни округляются вверх (`ceil`), подпись показывает целые дни |
| Цели квартала/года не настроены | Значения по умолчанию 300 / 1000 км, поля редактируются прямо в карточке |
| Новая функция не должна ломать `renderAll()` | Расчёт — чистая функция; отрисовка — отдельная `renderGoalForecast()`, вызывается из `renderAll()` |
| Зависимость от task-005 (KPI-карточка) | Базовый P0 не зависит от task-005; зависимость только у P1 |
