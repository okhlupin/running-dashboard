### Задача

Приложение показывает «сколько набегано из скольких нужно», но не отвечает на вопрос «**когда** я добегу цель». Нужно добавить прогноз даты достижения цели по текущему темпу — для месяца, квартала и года.

**Что обязательно сделать (P0):**

1. **Чистая функция расчёта.** Добавь в раздел «2. ЧИСТЫЕ ФУНКЦИИ РАСЧЁТОВ» (сразу после `calcGoalForMonth`, ~строка 1440) функцию:

   ```js
   /**
    * Прогноз достижения цели по текущему темпу.
    * @param {number} goalKm        — цель периода, км
    * @param {number} actualKm      — уже набегано за период, км
    * @param {number} paceKmPerWeek — текущий темп, км/нед
    * @param {string} todayISO      — сегодня (YYYY-MM-DD)
    * @param {string} targetISO     — последний день периода (YYYY-MM-DD)
    */
   function calcGoalForecast(goalKm, actualKm, paceKmPerWeek, todayISO, targetISO) { ... }
   ```

   Она **не читает DOM, не обращается к `state` и не имеет побочных эффектов** — только считает и возвращает объект. Её можно вызвать из консоли и проверить на тест-векторах.

2. **Формулы — строго по спецификации** (иначе результаты не сойдутся с ожиданиями):

   ```
   remainingKm        = max(0, goalKm - actualKm)
   daysLeft           = кол-во календарных дней от today до target включительно
   requiredKmPerWeek  = remainingKm / (daysLeft / 7)
   paceDeltaKmPerWeek = paceKmPerWeek - requiredKmPerWeek
   daysNeeded         = ceil(remainingKm / paceKmPerWeek * 7)      // только при pace > 0
   forecastDateISO    = addDaysISO(today, daysNeeded - 1)          // сегодня = 1-й день
   status:
     'achieved' — actualKm >= goalKm
     'no-data'  — paceKmPerWeek <= 0 && remainingKm > 0
     'on-track' — forecastDateISO <= targetISO
     'behind'   — forecastDateISO > targetISO
   daysEarly = max(0, daysLeft - daysNeeded)
   daysLate  = max(0, daysNeeded - daysLeft)
   ```

   **Обрати внимание на `- 1` в `addDaysISO`** — сегодняшний день считается первым днём накопления, иначе «на N дней позже» будет считаться на день больше.

3. **Темп прогноза.** `paceKmPerWeek = sumKmInWindow / (windowDays / 7)`, окно **календарное** (от сегодня назад), тренеры берутся через `getRunsByTypeOnly()` — то есть фильтр типов влияет на прогноз так же, как на остальные метрики. Окно по умолчанию 28 дней, варианты 7 / 28 / 56 / 90 через `state.settings.forecastWindowDays`.

4. **Факт за период** — сумма км по тренировкам в границах выбранного периода **и** с учётом фильтра типов.

5. **Карточка «📅 Прогноз достижения цели»** в левой колонке, сразу после карточки «🎯 Недельный план и Цель месяца» (после строки ~880). Внутри:
   - переключатель периода `Месяц / Квартал / Год`;
   - крупная строка прогноза: дата + статус-бейдж;
   - «Факт» и «Осталось»;
   - «Темп сейчас» и «Нужно темп», дефицит подсвечивается красным;
   - прогресс-бар цели (используй существующий `.progress-mini`);
   - подпись с окном расчёта темпа;
   - поля целей квартала и года.

6. **Цели квартала и года** — новые поля `state.settings.forecastGoals = { quarter: 300, year: 1000 }` с полями ввода и сохранением через существующий `saveAllState()` → `localStorage['run_pro_settings_v2']`.

7. **Цель месяца берётся из существующего механизма** `calcGoalForMonth(ym, state.goals)` — новую логику хранения целей не заводить.

8. **Строка в шапке с бегуном.** Дополни `runner-status-text` (строка ~1767) прогнозом:
   `Цель месяца (2026-10): 88.0 / 75 км (117%) · Прогноз: 26 окт, на 5 дней позже`.
   Строка должна остаться в одну строку на широком экране и не ломать анимацию бегуна.

9. **Отрисовка** — отдельная функция `renderGoalForecast()`, вызывается из `renderAll()` (строка ~3534). Пересчёт — при любом изменении периода, окна, цели, фильтра типов и данных.

### Жёсткие ограничения (сломать нельзя)

- **Не трогай** `state.goals`, `calcGoalForMonth`, `state.plans`, `calcPlanForDate`, `renderKPIs`, `updateRunnerPositionAndStatus` в части расчёта прогресса — только **дополни** строку статуса.
- **Не ломай** `renderAll()`, экспорт/импорт JSON, CSV-импорт, настройки пульсовых зон, ИИ-ввод голосом, демо-данные «⚡ Демо-данные (60)».
- **Новые ключи в экспорт JSON с тренировками не попадают** — они живут в `state.settings`.
- **Темы.** Только существующие CSS-переменные (`--accent`, `--danger`, `--amber`, `--blue`, `--muted`, `--border`, `--card`, `--bg-elev`). Новые элементы обязаны читаться в тёмной и светлой темах.
- **Стиль кода.** Именование в стиле файла (`forecast-card`, `forecast-status`, `renderGoalForecast`), комментарии на русском в стиле существующих (`/* ==== ... ==== */`), никаких новых глобальных переменных без префикса `forecast`.
- **Русские окончания** («43 дня», «5 дней», «1 день») — через общий хелпер, а не строковой конкатенацией вида `дней`.

### Обязательные тексты интерфейса

| Статус | Бейдж | Подпись |
|---|---|---|
| `achieved` | 🎉 Цель уже достигнута | `Факт 78.0 км при цели 75.0 км` |
| `on-track` | 🎉 Успеваем | `Прогноз: 26 окт — на 5 дней раньше срока (31 окт)` |
| `behind` | ⚠️ Отстаём | `Прогноз: 12 фев — на 43 дня позже срока (31 дек)` |
| `no-data` | ⛔ Нет данных о темпе | `За 28 дней нет тренировок — нужен темп 40.3 км/нед` |
